\section{Conclusion}
\label{sec:conclusion}

We measured how much an edit to an earlier, updated value shifts a language model's candidate scores for a query about the associated entity, relative to a query about the other entity. In seven models from five families this sensitivity depends more on where and how the value is mentioned (in which relative position, with the entity or alone, with or without \lit{Previously}) than on whether the value was ever assigned to the queried attribute. Among the tested contrasts, mention order produces the largest changes in every model. An entity mention outweighs a superseded assignment in six of the seven, by more than relation status in five; in Mistral-7B the construction difference changes sign with order. Relation status ranges from a negative effect in Mistral-7B, through no detectable effect in Gemma 3 4B and Falcon3-7B, to about a quarter of superseded relevance in Qwen3-14B. The same ranking holds in two models that narrowly fail the competence screen. The directions of the finer order and marker effects differ between models, and the construction gap persists in the tested templates when the name--value token gap is matched. In Qwen, a follow-up with different prompts finds a positive effect of queried-attribute status and a negative effect of updating, consistent with the two partly cancelling, and in a score-only run its sensitivity to the immediately superseded value grows with chain depth; Gemma 3 4B shows neither pattern clearly. Because the screened models have near-ceiling current-candidate ranking, these are statements about candidate scores, not generated answers. Studies of how models handle updated information should control the construction and order of earlier mentions, and report results per model, before attributing residual sensitivity to obsolete assignments.
