## Hypotheses and estimands

H1: With current state, policy and answer fixed, the obsolete state implying a wrong action increases wrong-action preference relative to an obsolete state implying the correct action. For A–D, L=log P(canonical wrong label + EOS | prompt)-log P(canonical correct label + EOS | prompt), and D_c=mean_history(L_old-wrong-L_old-correct). Positive D is interference in preference, not automatically a generated failure.

H2: D_superseded differs from D_updated_other. Primary Delta_semantic=D_superseded-D_updated_other is two-sided. D_superseded-D_entity_mention is a prespecified secondary contrast. Report aligned and reversed strata separately even if their signs disagree. Equal token lengths do not isolate semantic representations; this is a prompt-edit experiment.

H3 is secondary: easy retrieval sensitivity improves held-out prediction of strict downstream failure beyond simpler predictors. It can be false without invalidating H1/H2. Original E(q)=(m_after(replacement)-m_after(source))-(m_before(replacement)-m_before(source)); original R averages E(target current query)-E(other current query) over both edited entity bindings. Here R_easy_local=E(target)-E(other) for one edited entity per concrete history, with source=old-wrong, replacement=old-correct. Retrieval uses the original bounded spaced/unspaced/title surface proposal rule on four states. Four states, one edited target, the new templates and paired state constraints change the estimand; **R_easy_local is not the original symmetric R**. All easy scores and direct generations are checkpointed before any downstream forward; both intervention members are available before downstream decisions. Scores for both members determine the predictor, never downstream outcomes.

Baseline predictors: easy current–historical bounded log-mass margin, historical candidate log mass, easy answer confidence normalized over four bounded candidate classes, downstream correct-action confidence normalized over the two canonical EOS events, actual edited-token position and downstream prompt length. Action confidence is normalized only within scored events, not total answer probability; canonical valid mass is reported separately. Fixed nuisance covariates cover task, difficulty, vocabulary, order and construction. Use fixed C=1 L2 logistic regression, standardization within each training fold, five history-grouped folds, no tuning. Compare out-of-fold log loss with/without R_easy_local, bootstrap paired mean improvement across histories. Invalid outputs count as failures; report their rate separately. One-class folds or no outcome variation make H3 unavailable, not positive. Run separately on development and held-out-template confirmation; within-split CV is not external generalization. History grouping does not establish vocabulary/policy/template transfer; group IDs are retained for future v2 studies.

## Construction and difficulty

Four labels, exactly two states per action. Each history has a current target state and two distinct obsolete alternatives; one maps to each action. State-label permutations shuffle per task/difficulty/vocabulary block from the saved seed, then rotate to balance all four labels in current and historical roles and under both correct actions; correct action and both entity orders are fully crossed with entity orientation. Candidate label order is fixed per task, with both response tokens equally often correct; policy-label display order is fixed within each randomized block. Natural states: active/pending/restricted/suspended; opaque: S1/S2/S3/S4. Natural labels carry prior meanings, so the explicit policy can disagree with ordinary language. Correct action labels are APPROVE/DENY or EAST/WEST; both occur equally often as correct within each task/grid. All prompts have fixed response instructions.

A: initial target clearance/routing assignment, followed by a final assignment.
B: initial archive tag of the same entity, itself updated later; target attribute assigned finally.
C: initial word mentioned by the same entity, without assignment.
D: initial unassigned word in corresponding historical slot. Both entity orders independently vary, preserving aligned/reversed configurations.
E: current-only competence case, without historical/competing lines.
F: one actual final target value edited, flipping its answer. Its initial assignments stay fixed. F has a fixed baseline action orientation for D_live and is never included in the stale D estimand or H3.

A–D share policy, query, archive-tag update block, final assignments, candidates, sentence counts and surrounding text within a history. Sequential: both historical entries then final blocks. Interleaved: first historical entry, one entity's final block, second historical entry, other final block. Competing: interleaved plus two fixed archived mentions of queried entities with relevant state words. This adds relevant competition, not appended unrelated distractors. Syntax differs across A–D (attribute assignment versus mention versus no entity); lexical priors, archive-tag relevance, tokenizer geometry, grid-associated policy mapping rotations and interleaving are remaining confounds. Interleaving is operationalized by historical/current order and may place the target update before the other historical entry. Held-out paraphrase changes introductory and query wording, not assignment grammar.

Access maps current clearance directly to action. Routing maps current routing state to a bin and bin to action; the supplied two-step lookup is mechanically equivalent to the saved policy. Validation regenerates the exact policy text and answer. No inference-generated data.

## Schema and integrity

JSONL: schema, split, seed, history_id, history_signature, task, difficulty, vocabulary/vocabulary_id, entities/entity_pair_id, policy/policy_id, policy_order, actions, currents, old_values=[old-wrong,old-correct], other_old/other_current, historical_order, current_order, order_stratum, template/template_id, family, member, pair_id, example_id, correct_state, answer, wrong_action, prompt and edit_span. The latter is an exact body character span, never a global search for the repeated policy value.

One replicate has 192 histories (2 tasks × 3 difficulties × 2 vocabularies × 2 current-action indices × 2 historical orders × 2 current orders × 2 entity orientations), 11 records/history: A–D two each, E one, F two. Development: seed 81001, one replicate, 2,112 records. Frozen gate: seed 81002, two replicates, 4,224. Confirmation: seed 81003, eight replicates, 16,896. Confirmation uses the heldout paraphrase only. Entity pairs are disjoint across splits (Dev/Gate/Eval pools); this guarantees concrete-history separation but adds an entity-name distribution shift. All members and constructions of a history remain in one split and bootstrap cluster. Signature includes both alternatives, sorted entity-current assignments and policy; ignores template and literal orientation. Cross-split overlap and duplicate histories fail, including swapped orientations and paired edits. Policy/template/vocabulary IDs support audits but are not independent sample units.

Every artifact uses exclusive creation. Dataset manifests bind dataset/config/code hashes, seed and prior-dataset hashes; CLI validation also regenerates each split and requires exact deterministic equality. Freeze binds code, config and this protocol text. Scoring manifests additionally bind actual tokenizer backend, chat template, special tokens, EOS, actual prompt/event audit, packages, model config, dtypes and device map. Immutable 40-hex model/tokenizer revisions are required. Each checkpoint row has a content checksum; a completion record binds the final score and easy files and run manifest. Analysis and gate eligibility require the completion record and verify all hashes and row checksums. Resuming rejects changed hashes, malformed complete lines, duplicate/unknown IDs, nonfinite scores, changed row metadata or parsing. Interrupted trailing bytes are preserved before truncation. Records fsync after each completed member. Missing records stop analysis; no silent deletion or score-based filtering.

## Scoring and generated outcomes

Actual fast tokenizer audits every downstream, target-easy and other-easy prompt before any model forward: candidate prefix preservation/collisions/overlap; every baseline/edit span and outside-span token equality; token counts and length changes. Geometry mismatches stop inference, not history exclusions or vocabulary selection. Unequal span lengths are disclosed. The exact actual chat template must preserve the body once; otherwise technical stop. Thinking is disabled via template argument where supported. A locally cached tokenizer-only audit is possible; it never downloads a model. Data-only tests use a mock tokenizer and cannot certify real tokenizer geometry.

Action event: one leading space, every token of the full action string, then the designated EOS token. No length normalization. The sum of the two disjoint events is `canonical_valid_mass`, not probability of every acceptable answer: alternative whitespace/EOS paths are excluded. Easy retrieval mass retains original unterminated prefix events; never call it complete-answer probability. All scores must be finite.

Separately greedy generation, do_sample=False, num_beams=1, maximum 16 new tokens, designated EOS termination. Preserve text and token IDs. Strict parse strips only outer whitespace and accepts exactly a label; Markdown, explanatory text and multiple labels are invalid. Report correct, wrong, invalid; relaxed unique whole-label extraction is diagnostic only. Token-cap termination is invalid even if remaining text looks exact. Direct-retrieval greedy generation is also saved. No stochastic decoding search.

## Confirmation and decisions

Freeze all rules before confirmation data. H1 primary D_superseded and H2 primary Delta_semantic are reported per task, per model, using 97.5% percentile history-bootstrap intervals (two tasks, Bonferroni within each hypothesis family). H1 supports a directional preference effect when the interval lower bound exceeds zero. H2 supports difference when its interval excludes zero; no assumed direction. Secondary construction, order/difficulty/vocabulary strata and generation differences use descriptive 95% intervals; no multiplicity-adjusted claim about these. Bootstrap seed 81004, 2,000 independent reproducible draws, average paired effects within histories first. No architecture pooling. All predefined grid cells remain in reports even when they fail competence; label their feasibility status. Interpret task-wide confirmation estimates as the fixed-grid average, not a hand-selected difficulty.

No statistical significance, D, Delta or R correlations may choose models/tasks. Initial model is the reference Qwen pin only; adding models requires a new frozen model list before inspecting effects. Gate each task/difficulty on strict direct current retrieval >=95%, E strict downstream accuracy >=90%, downstream invalid <=5%, easy invalid <=5%. Behavioral focus requires historical strict downstream accuracy in [65%,95%]. These are feasibility criteria, not results. Gate report records counts and all cells; historical accuracy may categorize feasibility, never select according to intervention effects. A ceiling cell remains score eligible and supplies no generated-vulnerability claim. Confirmation generation requires a recomputed passing frozen gate and disjoint prior datasets. If none passes, stop confirmation, report feasibility failure and create v2 for redesign. No optional stopping: fixed sample sizes; stop only on technical invalidity, failed gates or resource limit, preserving partial results without confirmatory inference. No score-based exclusions or replacement histories.

The reference model runtime follows the repository's prior `downstream_transfer_v1` Qwen setup: FP16 compute, bitsandbytes int8 weight quantization, SDPA attention and automatic device mapping, using the same immutable model and tokenizer revision. This matches the nearest prior experiment's inference configuration. Unlike the single-GPU cross-model panel configs, `device_map: auto` permits Accelerate dispatch; actual placement is recorded and offload may increase runtime. Install the model extra to provide bitsandbytes. This is an implementation match, not a claim that int8 and unquantized scores are identical.

## Feasibility estimates and unresolved risks

Per member, action scoring <=3 forwards; two easy queries each <=17 forwards (four states × <=four surfaces plus initial). Two greedy responses <=32 steps. Conservative total <=69 forwards/member: development 145,728; gate 291,456; confirmation 1,165,824; all splits 1,603,008/model. Context sharing and KV caches can reduce real costs; this scorer does not batch suffix scoring. Actual token audit gives exact score-event counts; 69 excludes load/smoke overhead. At an assumed 10–100 forwards/sec, all splits take roughly 4.5–44.5 GPU hours/model, plus load overhead; this is an unmeasured scenario range, not a benchmark. Slow offload/long multi-token suffixes may greatly increase time. Stage 2 must measure runtime in development and obey a preallocated budget, without effects selecting variants.

Dataset/score/audit estimate 12 KB/member (~280 MB all splits), conservatively reserve 1 GB/model for JSON artifacts. The frozen run uses int8 weights with FP16 compute; quantized weights reduce weight storage versus the roughly 16 GB decimal FP16 payload, while KV cache, non-quantized modules, CUDA workspaces and dispatch overhead remain. GPU memory feasibility and real throughput are unmeasured; check available memory on the target machine before Stage 2. Download cache can need additional shard space. No GPU or tokenizer empirical audit was performed in Stage 1.

Risks: natural-language policy priors; syntactic construction differences; entity pool shift; small stratum cluster counts; four-state R adaptation and asymmetric edited entity; canonical EOS mass undercounting acceptable answers; malformed model responses; fixed-grid ceiling or floor; same-split H3 CV lacking template-transfer evidence; offload/runtime uncertainty. These do not justify silent changes. Prediction can remain unavailable if generation is perfect. Score findings alone cannot support overt failures or semantic-mechanism claims.
